Versions

Settings

Local JSON backup

Always saves as pr-tracker-data.json (same name, overwritten). Live data also stays in this browser (localStorage).
No folder linked yet.

Import / export all

Full backup of everything (issues, PRs, destinations, versions, lists, and link settings). Each page also has its own Export / Import for that section only.
Section files are tagged with a section field. Importing a section only updates that part (merge by id/name). Import all replaces the whole dataset after confirmation.

Cloud sync (GitHub Gist)

Multi-device sync without a custom server. Your data is encrypted in the browser with your passphrase, then stored in a private GitHub Gist. GitHub Pages only hosts the app UI — never plain data.
Security model
1) Passphrase — only you know it; used to encrypt/decrypt (AES-GCM + PBKDF2). Never sent to GitHub in plain form.
2) GitHub token — fine-grained or classic PAT with gist scope only. Stored in this browser’s session only (cleared when the tab closes), not in the Gist.
3) Gist ID — points at your private encrypted file. Safe to copy to your other devices.
Recovery: passphrase + token + Gist ID (or Export all JSON as offline backup).
Locked — unlock to sync.
While unlocked, every edit is uploaded to your private Gist automatically. On another device: Unlock → Pull now (manual). No automatic cross-device sync. Credentials stay in this browser only.
While unlocked, each save updates the private Gist (debounced ~1.5s so rapid edits batch). Each push also writes a dated backup file inside the same Gist (last 5 kept). GitHub also keeps Gist revision history. Token: Developer settings → PAT with only gist scope.

Jira links

Optional: build browse links from a Jira key (no API / login).
Example: http://jira:8080/browse → key CAR-123 becomes …/browse/CAR-123.

Branch name maintenance

Temp branches should follow Temp_<ver>_<Company> (capital T). Masters are left unchanged.

Azure DevOps / TFS repo

Branch names become clickable when a repo URL is set. Path templates use placeholders: {branch}, {ver} (digits from branch/version), {company}, {name}.
Example result: masters/v14_master → ?version=GBmasters%2Fv14_master
Example: branch Temp_14_Asia → master_dev/Temp/v14/Temp_14_Asia
Comma-separated. Example: developer → ?version=GBdeveloper (ignores master template).
Optional per-destination override: set “Azure path override” when editing a master/temp.
